# Roll For Honor project instructions

Follow the RFH skill and the project workflow in SecondBrain for architecture,
milestone scope, naming and publication. Preserve unrelated local editor settings.

## Visual development history

For meaningful visible changes to Godot scenes or UI, capture real rendered
screenshots as part of verification and preserve them in
`docs/development-history/YYYY-MM-DD/`. Update the history index with the scene,
development stage, renderer and relevant source revision or local-change status.
Capture representative states such as startup, flight and impact when relevant.
Use descriptive, unique filenames and retain earlier milestones; never overwrite
existing historical images with a newer state. Keep temporary capture scripts
and logs outside the repository. Record unavailable captures honestly; headless
test success alone does not establish visual verification.
